## Overview

Routine API authentication failures clear the transient session and reinitialize the
client, but preserve `rememberMeToken` and `deviceId`. These values are device-trust
anchors for MFA-gated regional backends.

## Usage

Use the explicit reset flow when the user asks to start over:

```swift
try await account.resetSession(modelContext: modelContext)
```

This clears the auth token, device-trust anchors, and API client before logging in again.

## API Reference

### `resetSession(modelContext:)`

Performs a user-initiated full session reset and persists the cleared trust anchors.

### `handleAPIError(_:modelContext:)`

Internal recovery path for re-authentication. It preserves trust anchors and refreshes
vehicles after a successful re-login.

## Notes

Device registration, successful login, and MFA completion save the model context eagerly.
This avoids losing the trust anchors or newly issued session when the app is terminated
before SwiftData autosave runs. Password, PIN, and serialized auth tokens are never stored
in SwiftData after migration; they are read and written through `KeychainService`.
